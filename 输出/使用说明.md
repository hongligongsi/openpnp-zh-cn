## 二、汉化包规格

- **来源**：OpenPnP 官方仓库 main 分支 `src/main/resources/org/openpnp/translations_zh_CN.properties`
- **条目数**：1947 条
- **汉化覆盖**：1936 / 1947 ≈ **99.4%**
- **编码**：UTF-8（无 BOM）、LF 换行
- **格式校验**：1947 条目零格式错误、零重复 key、零转义问题

> 相比官方原版，补齐了 32 个官方尚未翻译的条目（详见第四节）。

## 三、安装方法（三种任选）

### 方法 A：替换已安装 OpenPnP 内的资源文件（推荐）

1. 打开 OpenPnP 安装目录，找到 `lib` 目录（或位于其中的 `pnp-*.jar` 之类文件）
2. 用 7-Zip / Bandizip 打开该 jar
3. 把本包 `translations_zh_CN.properties` 拖进去，覆盖路径：
   ```
   org/openpnp/translations_zh_CN.properties
   ```
4. 启动 OpenPnP → **菜单 → Language → Chinese (Simplified) / 简体中文**

### 方法 B：装官方原版 + 本汉化文件

1. 从官网下载原版安装包：
   - Windows 64 位：https://s3-us-west-2.amazonaws.com/openpnp/OpenPnP-windows-x64-main.exe
   - 全部下载：https://openpnp.org/downloads/
2. 安装后按方法 A 替换资源文件

> Windows 下载速度慢属正常现象（S3 源 + 国内网络），建议用下载工具挂着。

### 方法 C：直接用官方版内置中文

官方 main 分支已自带中文资源（即本文件的原始版本）。装完官方版直接在
**Language** 里选简体中文即可，完成度已有约 98%。本包在此基础上再补 32 条。

`OpenPnP-2.6.1-深度汉化-by M.exe` 这个第三方整合包 **已整体损坏**，
不只是汉化文件的问题：

**内嵌资源完整性检查结果 — 39 个条目中 33 个损坏，仅 6 个完好**

| 类别 | 状态 |
|---|---|
| `translations_zh_CN.properties`（汉化） | 截断，CRC 不符，68% 内容乱码 |
| JRE 运行时（jvm.dll、awt.dll 等） | 大量解压失败 |
| Python 库（Lib/、pip/、setuptools/） | 大量截断 |
| 图片、音频资源 | 解压失败 |

汉化文件的具体损坏数据：

| 校验项 | ZIP 声明值 | 实际值 |
|---|---|---|
| 解压后大小 | 381,853 字节 | 380,359 字节 |
| CRC32 | `5BF3F382` | `9D9C52C3`（不匹配） |

损坏发生在 **deflate 压缩数据层**，原始内容已丢失，无法修复。
推测是打包或上传/下载过程中文件被破坏。**该包建议直接删除。**

同样提醒：该文件**没有数字签名**，来源不明，即使能运行也不建议使用。

### 技术原理与安全性

- Java class 常量池中 `CONSTANT_Utf8(tag=1)` 为「长度前缀 + 字节数据」，可**就地重写**
- 常量池**索引不变** → 所有引用无需改动
- 字节码偏移是**相对 `code[]` 起始** → 与常量池无关，不受影响
- 因此：只要保持常量池条目数量不变，替换字符串数据是**完全安全**的

**占位符安全校验**：每条译文都强制校验
`\x01` 占位符数量、`%s/%d` 格式符、花括号 `{}` 数量与原串一致，
任何不符即拒绝应用。三轮累计拦截 10 条（占位符丢失 / 首字符缺失），全部修正后通过。

三重验证均通过（**第三轮后重新执行**）：

|---|---|---|
