## 第二批：class 常量池汉化补丁（用户反馈「问题与解决方案」面板仍全英文）

### 问题定位

「问题与解决方案」（Issues & Solutions）面板的问题简介/解决方案文字
**不在 properties 文件中**，而是**硬编码在 Java class 的常量池字符串**里，
运行时由代码动态拼接（`\x01` 作为变量占位符，例如
`Nozzle tip \x01 has an invalid Min. Part Diameter of \x01.`）。
→ 无论 properties 汉化多完整，这些内容都仍是英文。

用例：截图显示 `To continue, the machine must be enabled and homed.`、
`Depending on the type of nozzle tip or shade...`、`Min. Part Diameter` 系列等。

### 技术方案：class 常量池就地重写

核心洞察（非常重要，可复用）：
- `CONSTANT_Utf8(tag=1)` = `tag(1) + length(2, BE) + bytes[length]`，**可安全就地重写**
- 常量池**索引不变** → `CONSTANT_Class/String/NameAndType` 等引用无需改动
- 字节码偏移（`LineNumberTable`/`StackMapTable` 等）**相对 `code[]` 起始**，
  与常量池无关 → 不受影响
- 唯一约束：**常量池条目数量必须保持不变**

**结论：替换 class 常量池字符串不需要任何字节码重写工具（不必 javac/jasm），
纯 Python 即可，且完全安全。**

### 实现

- `工作区/class_patch.py` — 重写器（`parse_cp` / `get_utf8` / `rebuild`）
  - 注意 CP tag 字节宽度：1=变长；7/8/16/19/20=3；15=4；
    3/4/9/10/11/12/17/18=5；5/6(Long/Double)=9 且**占两个槽位**（idx+=2）
- `工作区/patch_map.py` — 170 条中英映射表 `FULL{旧:新}`

### 关键工具
- **`translation_pipeline.py`**：占位符安全校验。译文用 `§` 表示 `\x01`，
  强制校验占位符数量 / `%s %d` 格式符 / 花括号数量与原串一致，
  不符即拒绝。本轮实际拦截 1 条（`吸嘴` 漏掉 `§`），修正后通过。
- **`struct_verify.py`**：按 class 规范逐字节解析
  `CP → access_flags → this/super → interfaces → fields → methods → attrs`，
  要求解析终点 == 文件长度。原版与补丁版均 2104/2104 OK。

### 重要教训
1. **`to_translate2.json` 是 `{字符串: [所在class]}` 的 dict，不是 list**。
   早期脚本误当 list 用导致 `KeyError: slice`；用 `set(d.keys())` 才是候选全集。
2. **未命中 ≠ 错误**：早期批次里 95 条「未命中」全是我臆造的 key
   （真实常量池中不存在），或大小写/尾空格不符。只有真实命中才应用，
   无害。但统计覆盖率时必须用**真实的 dict key 集合**，不能用臆造表。
3. **批次可能重复覆盖**：`batch4c` 的 `final visionOffsets §` 是大小写问题
   （真实为 `Final visionOffsets §`）。合并时用 `final` 字典去重即可，
   后续批次的同一 key 覆盖前者。
